# 06 — UI/application independent review

Reviewed baseline: `a06d405e01095309617069e43c5d4be9200c0ebc`.

Scope: `src/Cmdr/Program.cs` and all TUI application/controller, host/window, dialog/form, details/selection, list/tree/layout, status, recent-picker, argument/environment/stop-input editing, and command-line formatting code. Read the corresponding tests in full and the complete README. Output-specific algorithms (`OutputView`, `OutputWrap`, `OutputScroll`, `DisplayLines`, `TextWidth`, `ColorMap`, `SelectionText`, `Osc52`) are excluded from findings; their application-facing call sites were inspected. Relevant session/config/process contracts were read to establish reachability and ownership, without duplicating their separate reviews.

**Result:** six distinct findings below: five P2 and one P3. A separate shutdown reproduction supports session finding **05-01**, with cancellation considerations in **05-03**; it is cross-referenced rather than assigned a duplicate 06 ID. No additional P1 finding is asserted here. All six local findings have Linux executable evidence. For 06-05, formatter output and Linux PowerShell behavior were executed; Windows/cmd.exe behavior remains static analysis.

## Functionality overview

`Program` selects version/usage, a recent-config picker, or a directly loaded session. The host owns the Terminal.Gui application and restores it in `finally`; session ownership is explicit between direct and picker entry paths. `MainController` builds list, details, output and status panes, handles action targets and dialogs, preserves focus across tree edits/collapse, marshals session notifications, and updates views on timers. Add/edit dialogs convert field values through pure form helpers and commit only after validation. Details resolve inherited cwd/environment, retain logical text selections through wrapping, and expose scrolling. Quit resolves unsaved changes, offers graceful stop/force kill/cancel, and polls active processes while the UI remains responsive.

## Verified findings

### 06-01 — P2: Accepting the command editor silently changes arguments containing newlines

- **References:** `src/Cmdr/Tui/ArgsText.cs:15-21`, `:35-41`; `src/Cmdr/Tui/CommandDialog.cs:101`, `:264`; `src/Cmdr/Tui/CommandForm.cs:99`. Existing coverage: `tests/Cmdr.Tests/ArgsTextTests.cs:55-69`.
- **Trigger:** Load a valid command with arguments such as `["-c", "echo first\necho second"]`, press F2, and accept without changing the arguments (or change an unrelated field).
- **Impact:** The editor commits `["-c", "echo first", "echo second"]`. For a shell command, this changes the script and the meaning of later arguments; saving permanently replaces the original definition. A literal carriage return at an argument's end is also discarded. JSON arguments and direct launching support these characters; the editor has no warning or escaping mechanism for them. This violates the edit workflow implied by `README.md:75-76` and its definition of arguments as individual array elements.
- **Evidence:** A probe instantiated the actual `CommandDialog` on Terminal.Gui's ANSI buffer driver, supplied the above spec, laid out the dialog, and invoked its normal `TryCommit` conversion. It returned `True` and the commit callback received `["-c","echo first","echo second"]`. The helper round trip independently produced the same result. `Format` writes data newlines indistinguishably from argument separators; `Parse` unconditionally splits them. Existing round-trip cases contain empty arguments and spaces, but no newline/carriage-return data.
- **Fix direction:** Use a reversible representation for individual arguments (for example JSON strings per row or a structured argument list with explicit escape handling). Preserve unchanged arguments if the UI cannot yet represent them; do not silently reinterpret them. Document the chosen entry syntax.
- **Regression test:** Load, open and accept an existing command without changes, then compare the entire argument array. Cover embedded LF, CRLF, a final CR, empty arguments and literal backslashes. Include an edit to another field and a save/reload to prove those paths retain the arguments too.

### 06-02 — P2: Environment editing can silently split one value into extra variables or removals

- **References:** `src/Cmdr/Tui/EnvText.cs:13-24`, `:37-64`; `src/Cmdr/Tui/CommandDialog.cs:98`; `src/Cmdr/Tui/GroupDialog.cs:95`, `:185`; `src/Cmdr/Tui/CommandForm.cs:101`, `:239-246`. Existing coverage: `tests/Cmdr.Tests/EnvTextTests.cs:101-109`.
- **Trigger:** A command or group has a valid environment value containing a newline followed by text that itself resembles an environment directive, e.g. `{ "A": "first\nB=second" }`. Open its editor and accept without editing the environment.
- **Impact:** The saved overlay becomes `{ "A": "first", "B": "second" }`; a continuation beginning with `!B` can instead become a removal. Ordinary multiline values whose continuation lacks `=`/`!` prevent even an unrelated edit from being accepted. A trailing CR is lost as well. This can alter command behavior and, for a group overlay, affect every descendant. README environment values are not restricted to single lines.
- **Evidence:** The actual command-dialog probe accepted the original overlay and its callback received `{"A":"first","B":"second"}`. The independent helper probe returned **zero parse errors**. Contrary to `EnvText.cs:13`'s comment that multiline values produce an error, a continuation with valid directive syntax is accepted as another entry. The group dialog uses the same formatter/parser path, so it has the same conversion defect. Existing round-trip coverage only uses single-line values.
- **Fix direction:** Provide reversible escaping or a structured editor for values, including CR/LF and literal backslashes. If preserving the current syntax, detect unsupported original values and preserve them or clearly block unsafe conversion before committing; changing the comment alone is insufficient.
- **Regression test:** Exercise command and group edit/accept/save/reload with values containing LF, CRLF, final CR, blank lines, `B=second` and `!B` continuations. Assert exact dictionary equality, no extra variables/removals, and that unrelated edits work without replacing the environment.

### 06-03 — P2: Valid placeholder sets can place required input fields outside the visible dialog

- **References:** `src/Cmdr/Tui/InputDialog.cs:38-56`; requirement `README.md:180-186`. `tests/Cmdr.Tests/InputFormTests.cs` tests conversion/validation, not actual dialog geometry.
- **Trigger:** Start a command/group with more distinct placeholders than fit vertically, or use one long legal placeholder name. No placeholder count or name-length limit prevents either case. Terminal shrinkage produces the same class of layout problem.
- **Impact:** Some required fields cannot be seen while being entered, and validation still requires them. Keyboard focus can move to an invisible field without revealing it; a long label can put even the sole field wholly beyond the right edge. This makes documented input prompting unusable for valid configurations rather than merely truncating cosmetic text.
- **Evidence:** With a requested 80×24 screen and 30 required inputs, the real laid-out dialog had viewport `{X=0,Y=0,Width=69,Height=18}`; the last field was `{X=8,Y=29,Width=60,Height=1}`. Calling `SetFocus()` on that field yielded `HasFocus=True` but left the dialog viewport at Y=0 and the field at Y=29. With a single 100-letter name, the viewport width was 77 while its field began at X=101. Height/outer width are capped, but child positions are not, and there is no scrolling form container or focus-reveal logic.
- **Fix direction:** Put fields in a vertically scrollable form that reveals the focused field, keep buttons outside the scrolling area, cap/wrap labels, and derive field width from the actual inner viewport. Recalculate on resize. Do not fix only by increasing the fixed dialog dimensions.
- **Regression test:** Lay out actual dialogs with 30 inputs, a 100-character name, long optional labels, and small/resized screens. Tab forward/backward to every field and verify its editable area is visible and can be filled, then accept all required values. Verify Escape still cancels without starting anything.

### 06-04 — P2: Expected config file/path errors escape both application entry paths

- **References:** `src/Cmdr/Program.cs:51-59`; `src/Cmdr/Tui/RecentPicker.cs:108-117`. Reachability: `src/Cmdr.Core/Config/ConfigStore.cs:114` reads the file outside its JSON exception conversion; `src/Cmdr.Core/Session/ConfigSource.cs:18` resolves `logsDir` during session construction.
- **Trigger:** Open an existing unreadable config, encounter an I/O failure while reading it, or load a JSON config with an unresolvable path such as `"logsDir":"bad\u0000path"`. Select the same file through the recent picker for the in-application variant.
- **Impact:** Rather than a concise startup error/exit 1, direct launch aborts with an unhandled exception. In the picker, the exception escapes the open action and ends the application instead of keeping the picker available for another file. JSON syntax errors already have a recoverable path, but these equally foreseeable user/file-system errors bypass it.
- **Evidence:** A subprocess opening a regular temporary config with permissions `000` exited by SIGABRT (`returncode=-6`) and printed `Unhandled exception. System.UnauthorizedAccessException`. Opening the NUL-containing `logsDir` config also returned -6 with `ArgumentException: Null character in path`. A live `RecentPicker` probe invoking `Open` on that config propagated `ArgumentException`. For comparison, malformed JSON returned the intended exit 1 with a `cmdr:` diagnostic. Both entry paths catch only `ConfigException`.
- **Fix direction:** Normalize expected file/path failures into contextual `ConfigException` at the load boundary, or consistently handle the known I/O/access/path exceptions at both entry points. Preserve the picker on failure and produce exit 1 for direct launch. Avoid broadly swallowing unrelated programming exceptions. Coordinate the shared load-boundary change with the configuration reviewer.
- **Regression test:** Subprocess-test a real unreadable file and invalid `logsDir`/base path; require a normal exit 1 and useful diagnostic without an unhandled stack. Test the recent picker opening a failing entry, acknowledging the error, then opening a valid entry successfully. Include an I/O read failure and preserve existing malformed-JSON handling.

### 06-05 — P2: Windows copied command lines quote for an argument parser, not for the shell that receives the paste

- **References:** `src/Cmdr/Tui/CommandLineFormatter.cs:6-9`, `:48-55`; clipboard caller `src/Cmdr/Tui/MainController.cs:810-819`; documented copy action `README.md:277`. Repository comparison: `src/Cmdr.Core/Processes/WindowsCmdEscaping.cs:11-12`, `:37-55` explicitly handles cmd.exe metacharacters for actual batch launching.
- **Trigger:** Copy a Windows command whose literal argument contains shell syntax without whitespace, such as `a&b`, `x|y`, `x>out` or `%TEMP%`, and paste the result into cmd.exe.
- **Impact:** The emitted command line changes argument values or invokes shell control/redirection/expansion. In particular, `&` becomes another command boundary instead of literal data. Direct launching correctly treats arguments as data; the copied text does not preserve that behavior. Quoted paths and PowerShell also need a specified shell contract, so choosing only by operating system is insufficient.
- **Evidence and verification boundary:** Executing the formatter's Windows branch on Linux produced exactly `tool.exe a&b x|y x>out %TEMP%`. `WindowsDelimiters` only tests whitespace and quotes; no shell escaping follows. This verifies the emitted-text defect. Additionally, the formatter emitted `/usr/bin/printf %s "$(Write-Output unexpected)"` for the literal argument `$(Write-Output unexpected)`. Running that emitted line in the available Linux PowerShell Core returned `unexpected`, proving that the copied text performed substitution instead of preserving the literal argument. Windows/cmd.exe interpretation remains static analysis, supported by this repository's separate cmd.exe escaping implementation; no Windows host, cmd.exe or Wine was available/executed. Existing `CommandLineFormatterTests` verify MSVCRT quoting, not shell paste equivalence.
- **Fix direction:** Choose and expose an explicit copy target (cmd.exe or PowerShell) and implement quoting/expansion handling for that shell, keeping display/native argument formatting separate where necessary. Reuse existing escaping knowledge only with care: a `/c` batch launch and an interactive paste can have different parsing layers. If retaining native command-line formatting, label that limitation instead of promising shell-paste text.
- **Regression test:** On Windows, copy and execute safe argument-echo commands through the supported shell, comparing received arguments byte-for-byte for `&`, `|`, `<`, `>`, `%`, `!`, quotes, trailing backslashes, spaces and empty strings. Use an external temporary marker to ensure shell syntax cannot run a second command or redirect output. Retain the current native-parser tests separately.

### 06-06 — P3: A transient status message never clears when the hint text is unchanged

- **References:** `src/Cmdr/Tui/MainController.cs:454-457`, `:1144-1161`; display state `src/Cmdr/Tui/StatusLine.cs:19-24`.
- **Trigger:** Save or perform any action that calls `ShowMessage`, then wait five seconds without changing the calculated Enter/action hints.
- **Impact:** The old success/error/refusal remains bold indefinitely and replaces the normal action hints, including the right-aligned Quit hint. Navigating among items with the same hint string does not restore them. This can leave obsolete error text on screen even though the controller has already considered it expired.
- **Evidence:** The probe built the actual controller, called `ShowMessage("Review temporary message")`, moved `_messageUntil` into the past, and invoked `OnFastTick`. Afterwards controller `_message` was null, but `StatusLine._text` was still `Review temporary message` and its message flag remained true. `ShowMessage` changes the displayed mode without invalidating `_shownHints`; expiry calls `ShowHints`, which returns early when the previously cached hint matches.
- **Fix direction:** Invalidate `_shownHints` when showing a message, or include the status display mode in the cache and explicitly restore hints on expiry.
- **Regression test:** With stable targets, show and expire a message under a controllable clock; assert normal hint text, non-message styling and the right-side Quit text are restored. Repeat with two successive messages and with unchanged versus changed Enter hints.

## Cross-review shutdown finding: supporting evidence for 05-01 / 05-03

Do **not** count this as a separate 06 finding. The root cause and remediation belong to [05-session-orchestration.md](05-session-orchestration.md), findings **05-01** (P1) and **05-03** (P2).

UI integration references: `src/Cmdr/Tui/MainController.cs:769-788` discards the restart task and supplies no cancellation token; `:881-887` enters quit independently. `src/Cmdr/Tui/QuitFlow.cs:49-54`, `:81-91` stops currently active work and waits on active counts without first invalidating pending restart launches.

Independent Linux probe: start a Python worker with a SIGINT handler that takes 700 ms to exit, begin the same background `Session.RestartAsync` call used by F5, wait for Stopping, then run the **actual `QuitFlow`** and select its default **Stop and wait**. A start-marker file showed a second PID starting during the waiting dialog. The probe observed `ActiveEntries.Count=1` and `restartCompleted=False` before quit, then `new process started while waiting, active=1`. It cancelled the wait dialog and explicitly force-killed/waited for the replacement during cleanup. Thus the UI symptom occurs for graceful quit too, not only the already-reported ForceKillAll path.

The regression test should include the actual controller/quit ownership boundary: settle/invalidate pending F5 operations before deciding shutdown has completed, and ensure cancelled quit does not revive old restart authority. Merely passing a token from the controller will not suffice until 05-03's cancellation checkpoints are fixed. No extra native process-tree defect is inferred from this result.

## Strengths and README alignment

- Pure helpers isolate most tree, form, selection, formatting, status and navigation policy from Terminal.Gui. Identity-based tree focus and collapse state avoid confusing rows rebuilt after an edit with the underlying item. Dropdown label disambiguation and descendant exclusion are thoughtful and directly tested.
- Base-file protections are applied before dialogs and again in session mutations; offered parent/target choices exclude imported groups. Details use each item's source directory, and source labels/read-only explanations are covered. The opened-file-only save and per-file resolution model match `README.md:191-197` in the inspected application paths.
- Stop input uses explicit reversible escaping with malformed-escape diagnostics. Required/optional inputs retain whitespace intentionally, map names case-sensitively, and are gathered before starts. Dialog commit errors leave the dialog available for correction, and cancel paths do not call commit.
- Main-window Escape is intercepted, while dialogs retain cancellation. Tab/Shift+Tab explicitly traverse the three panes. Live key-dispatch probes confirmed list navigation skips command detail rows, marking works, collapse transfers focus to the header, and pane traversal works in both directions.
- Session notifications are coalesced and marshalled to the UI; ordinary process waits run off the UI thread. Quit polling keeps its modal UI alive and removes its timer in `finally`. Application disposal is in `finally` for both entry paths. These are sound foundations, subject to the pending-restart lifecycle issue above.
- Dirty-title updates, explicit saves and save-error dialogs implement the README's persistence model. Details retain logical selection positions and copy original logical text across visual wraps; invalid cwd handling is tested instead of allowing redraw exceptions.

## Maintainability, extensibility, and non-defect recommendations

These are recommendations/risks, not additional verified bugs or severity-counted findings.

1. **Add integration seams around the controller.** `MainController` is 1,183 lines and combines key routing, modal execution, tree focus, operation dispatch, refresh scheduling and status state. Extract small testable action/lifecycle and status components; inject dialog and clock adapters. The new seams should make task ownership and visible status transitions explicit, addressing actual defects above rather than adding generic abstraction.
2. **Exercise real controls at the policy boundaries.** The existing UI suite has no references to `MainController`, `MainWindow`, `TuiHost`, `QuitFlow`, `RecentPicker`, or actual add/edit/input dialog construction. `ConfirmTests` checks index reversal, `FocusCycleTests` checks arithmetic, and form tests check records; they do not establish actual event propagation, focus visibility, default/cancel behavior, nested-modal timing, save failure recovery or shutdown coordination. ANSI buffer-driver tests are feasible, as the probes demonstrate.
3. **Review narrow-screen support as a product decision.** Command/group forms use fixed dimensions and the main list reserves at least 32 columns. Beyond the confirmed input-dialog problem, small terminals/resizes need an explicit supported layout or useful minimum-size feedback. No distinct crash is asserted for those forms without a reproduction.
4. **Avoid repeated full details recomputation if large descriptions/environments become common.** `DetailsView.Scroll` arranges the full content, and the 100 ms controller tick requests it for title updates; redraw/scroll/hit-testing can arrange it again and enumerate the process environment again. Cache by item/spec/process metadata and width if measurement warrants it. No measured performance regression is asserted here.
5. **Document form entry syntax and copy shell expectations.** README lists edit/copy capabilities, but not argument/environment/stop-input editor encoding. The fixes for 06-01/02/05 should establish an explicit reversible contract. README input prompting should remain unrestricted only once all requested fields can actually be reached visibly.
6. **Keep UI-thread contracts explicit when extending background actions.** Restart executes session methods off the UI thread while edits are allowed on it, whereas session documentation describes actions/edits as UI-thread operations. A future operation registry should define what state is snapshotted and serialize mutations appropriately. No additional reproducible collection race is claimed; the verified lifecycle failure is already assigned to 05-01.

## Limitations

Windows behavior was reviewed statically, supplemented by formatter execution and PowerShell Core execution on Linux; no Windows terminal/process environment, cmd.exe or Wine was used. Buffer-driver UI probes verify event routing, geometry, state and commits, not physical terminal rendering, terminal clipboard interoperability, real mouse drag behavior or interactive console shutdown signals. Output-specific algorithms and native process-supervision correctness remain with their assigned reviewers. No full-suite result is claimed here. Recommendations above are deliberately separated from reproducible findings; no speculative UI-thread race, terminal-width algorithm defect, or native process-tree failure has been promoted to a bug.
